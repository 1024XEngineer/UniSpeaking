> 状态：已确认
>
> 确认日期：2026-07-30
>
> 适用分支：`feature/profile-page`

## 1. 定位

个人中心定位为“账号与设置中心”，不是学习驾驶舱。

它负责：

- 展示和修改当前用户的昵称、头像；
- 展示必要的学习概览：本周学习时长、学习资产数量、连续学习天数、月度日历和成就；
- 复用自由对话已有的 AI 老师、英语水平和对话语速设置；
- 允许用户查看、编辑和清空长期用户资料；
- 提供修改密码、账户注销及注销恢复能力；
- 保留现有会员和支付演示逻辑。

它不负责：

- 新增学习目标、AI 学习建议、周报、月报或能力雷达；
- 重复实现学习资产列表、训练历史和评分报告；
- 修改会员、支付和额度逻辑；
- 调整现有个人中心布局和响应式样式；
- 直接读取其他业务模块的数据库表；
- 为当前规模提前增加缓存、消息队列或微服务。

## 2. 已确认约束

1. 不修改其他模块已经开发完成的代码；必须修改时，先列出文件、原因和影响并取得授权。
2. 允许新增开发文档，文档只能写入 `docs/`。
3. 每一个较大的修改独立提交一次 commit。
4. SQL 表名和字段名使用 `snake_case`；Java 字段和 JSON 字段使用 `camelCase`。
5. 现有字段沿用原名；只有现有模型不存在的字段才新增。
6. 用户头像保存在对象存储，关系数据库只保存对象键。
7. 修改密码后 `auth_version + 1`，所有设备立即退出。
8. 账户注销后立即进入待删除状态，保留 30 天，期间允许撤销；到期后永久删除。
9. 成就系统采用独立定义表和用户进度表。
10. 个人概览使用页面级聚合查询，但聚合服务只能调用其他模块公开的查询端口。

## 3. 当前实现基线

### 3.1 已存在的真实能力

- `GET /api/auth/me`：读取当前用户；
- `GET /api/user-preferences`：读取 AI 老师、语速、英语水平和长期用户资料；
- `PUT /api/user-preferences`：更新上述偏好；
- JWT 中包含 `auth_version`，后端会与 `"user".auth_version` 比较；
- BCrypt 密码编码；
- `"user"` 表已经包含 `nickname`、`status` 和 `auth_version`；
- `user_preference` 已经包含 `preferred_voice`、`preferred_ai_speech_speed`、`cefr_level` 和 `memory_text`；
- 前端 `SpeedSelector`、`LevelSelect`、`TeacherSelector` 已同时被自由对话和助手设置复用。

### 3.2 当前仍为 Mock 的能力

- 本周学习时长；
- 已保存学习资产数量；
- 连续学习天数；
- 学习日历；
- 近七天练习节奏；
- 成就定义和用户进度；
- 会员套餐、额度和支付；
- 修改密码和注销账户按钮。

会员和支付继续保留 Mock；其余个人中心数据需要接入真实服务。

## 4. 系统边界

```text
Browser
  |
  | JWT
  v
ProfileOverviewController
  |
  v
ProfileOverviewService
  |-- AccountService -----------------> "user"
  |-- ProfileService -----------------> user_preference
  |-- LearningStatisticsQueryPort ----> 练习会话模块公开查询
  |-- LearningAssetCountPort ---------> 学习资产模块公开查询
  `-- AchievementService
         |-- AchievementMetricQueryPort -> 会话/资产/评分公开指标
         `-- AchievementRepository -----> achievement_definitions
                                        + user_achievement_progress

AccountService
  |-- UserAccountRepository ----------> "user"
  `-- AvatarStorage ------------------> 对象存储
```

### 4.1 边界规则

- `ProfileOverviewService` 是页面查询编排器，不是其他模块数据的所有者。
- 聚合服务不得直接注入练习、资产或评分模块的 MyBatis Mapper。
- 所有查询必须使用 JWT 中的当前用户 ID，不接受前端传入任意 `userId`。
- 学习资产卡片只负责导航到 `/assets`；资产详情和归属校验由学习资产模块负责。
- 首版不增加缓存。只有出现明确的慢查询或数据库压力后再评估。

## 6. 数据库设计

### 6.1 修改现有 `"user"` 表

保留现有字段：

```text
id
username
password_hash
nickname
role
status
auth_version
last_login_at
created_at
updated_at
```

新增字段：

```sql
ALTER TABLE "user"
ADD COLUMN IF NOT EXISTS avatar_object_key VARCHAR(512),
ADD COLUMN IF NOT EXISTS deletion_requested_at TIMESTAMPTZ,
ADD COLUMN IF NOT EXISTS deletion_scheduled_at TIMESTAMPTZ;
```

账户状态增加 `PENDING_DELETION`：

```sql
ALTER TABLE "user"
DROP CONSTRAINT IF EXISTS user_status_check;

ALTER TABLE "user"
ADD CONSTRAINT user_status_check
CHECK (status IN ('ACTIVE', 'DISABLED', 'LOCKED', 'PENDING_DELETION'));
```

约束：

```sql
ALTER TABLE "user"
ADD CONSTRAINT user_deletion_schedule_check
CHECK (
    (status = 'PENDING_DELETION'
        AND deletion_requested_at IS NOT NULL
        AND deletion_scheduled_at IS NOT NULL
        AND deletion_scheduled_at > deletion_requested_at)
    OR
    (status <> 'PENDING_DELETION'
        AND deletion_requested_at IS NULL
        AND deletion_scheduled_at IS NULL)
);
```

数据库不保存头像二进制或固定访问域名。接口根据 `avatar_object_key` 和对象存储配置生成 `avatarUrl`。

### 6.2 成就定义表

```sql
CREATE TABLE IF NOT EXISTS achievement_definitions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    code VARCHAR(64) NOT NULL UNIQUE,
    name VARCHAR(64) NOT NULL,
    description VARCHAR(255) NOT NULL,
    category VARCHAR(32) NOT NULL,
    metric_key VARCHAR(64) NOT NULL,
    target_value BIGINT NOT NULL,
    icon_key VARCHAR(64) NOT NULL,
    sort_order INTEGER NOT NULL DEFAULT 0,
    status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE',
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT achievement_target_value_check CHECK (target_value > 0),
    CONSTRAINT achievement_sort_order_check CHECK (sort_order >= 0),
    CONSTRAINT achievement_status_check CHECK (status IN ('ACTIVE', 'INACTIVE'))
);

CREATE INDEX IF NOT EXISTS idx_achievement_definitions_active_order
ON achievement_definitions (status, sort_order, code);
```

### 6.3 用户成就进度表

```sql
CREATE TABLE IF NOT EXISTS user_achievement_progress (
    user_id UUID NOT NULL,
    achievement_id UUID NOT NULL,
    progress_value BIGINT NOT NULL DEFAULT 0,
    unlocked_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (user_id, achievement_id),
    CONSTRAINT user_achievement_progress_user_fk
        FOREIGN KEY (user_id) REFERENCES "user"(id) ON DELETE CASCADE,
    CONSTRAINT user_achievement_progress_definition_fk
        FOREIGN KEY (achievement_id) REFERENCES achievement_definitions(id)
        ON DELETE RESTRICT,
    CONSTRAINT user_achievement_progress_value_check
        CHECK (progress_value >= 0)
);

CREATE INDEX IF NOT EXISTS idx_user_achievement_progress_unlocked
ON user_achievement_progress (user_id, unlocked_at);
```

不保存 `is_unlocked`。统一使用 `unlocked_at IS NOT NULL` 判断是否解锁，避免两个状态字段不一致。

### 7.2 修改昵称

```text
PATCH /api/account/profile
Authorization: Bearer <accessToken>
Content-Type: application/json
```

```json
{
  "nickname": "Yufan"
}
```

规则：

- 去除首尾空白；
- 允许 1–32 个字符；
- 不允许全空白；
- 返回更新后的 `UserAccountResponse`。

### 7.3 上传头像

```text
POST /api/account/avatar
Authorization: Bearer <accessToken>
Content-Type: multipart/form-data
```

表单字段：

```text
avatar=<image file>
```

规则：

- 最大 2 MiB；
- 允许 JPEG、PNG、WebP；
- 同时校验声明 MIME 和文件签名；
- 对象键格式：`avatars/{userId}/{uuid}.{extension}`；
- 先上传新对象并更新数据库，事务成功后再删除旧对象；
- 删除旧对象失败只记录不含敏感信息的错误日志，不回滚已经成功的新头像；
- 响应只返回 `avatarUrl`，不暴露 `avatarObjectKey`。

### 7.4 删除头像

```text
DELETE /api/account/avatar
Authorization: Bearer <accessToken>
```

规则：

- 先清空数据库中的 `avatar_object_key`；
- 再以幂等方式删除对象；
- 对象不存在视为成功。

### 7.5 修改密码

```text
PUT /api/auth/password
Authorization: Bearer <accessToken>
Content-Type: application/json
```

```json
{
  "currentPassword": "old-password",
  "newPassword": "new-password"
}
```

规则：

- 当前密码必须匹配；
- 新密码沿用注册接口 6–72 位规则；
- 新旧密码不能相同；
- 更新 `password_hash` 和 `auth_version + 1` 必须在同一事务中；
- 成功返回 HTTP 200，前端立即清除 Token 并跳转 `/login`；
- 所有旧 Token 在下一次请求时得到 `ACCESS_TOKEN_REVOKED`。

### 7.6 申请注销

```text
DELETE /api/account
Authorization: Bearer <accessToken>
Content-Type: application/json
```

```json
{
  "currentPassword": "current-password"
}
```

事务内完成：

```text
status = PENDING_DELETION
deletion_requested_at = now
deletion_scheduled_at = now + 30 days
auth_version = auth_version + 1
```

前端收到成功响应后清除 Token 并跳转登录页。

### 7.7 撤销注销

```text
POST /api/auth/reactivate
Content-Type: application/json
```

```json
{
  "username": "name@example.com",
  "password": "current-password"
}
```

规则：

- 只允许 `PENDING_DELETION` 且尚未到 `deletion_scheduled_at` 的账户；
- 验证用户名和 BCrypt 密码；
- 恢复为 `ACTIVE`；
- 清空两个注销时间字段；
- 再次增加 `auth_version`；
- 签发新的 `AuthResponse`；
- 与登录接口使用相同的错误信息，避免泄露账户是否存在。

`/api/auth/reactivate` 需要加入安全配置的匿名白名单。

### 7.8 长期用户资料

继续复用：

```text
GET /api/user-preferences
PUT /api/user-preferences
```

前端提供查看、编辑和清空 `memoryText` 的入口，不新增数据库字段。

## 8. 查询端口

个人中心新增以下只读端口。端口由个人中心声明，实现由数据所有模块提供。

```java
public interface LearningStatisticsQueryPort {
    LearningSummary summary(UUID userId, ZoneId zoneId);
    List<LearningCalendarDay> calendar(
            UUID userId,
            YearMonth yearMonth,
            ZoneId zoneId);
}
```

```java
public interface LearningAssetCountPort {
    long countSavedAssets(UUID userId);
    Map<LocalDate, Long> countSavedAssetsByDate(
            UUID userId,
            YearMonth yearMonth,
            ZoneId zoneId);
}
```

```java
public interface AchievementMetricQueryPort {
    long metricValue(UUID userId, AchievementMetricKey metricKey);
}
```

这些端口的实现是授权门：

- 实施前必须确认练习会话、学习资产和评分模块的公开查询边界；
- 未授权前不得在个人中心中直接新增跨模块 SQL；
- 不能用前端 Mock 数值作为生产降级；
- 数据不存在时返回零和空列表；数据库或服务异常时返回明确错误，不能伪装成零。

## 9. 成就同步策略

首版在读取个人概览时执行：

1. 查询所有 `ACTIVE` 成就定义；
2. 按不同 `metric_key` 去重后读取当前用户指标；
3. 计算 `progressValue = min(metricValue, targetValue)`；
4. 以 `(user_id, achievement_id)` 幂等 upsert；
5. 仅当第一次达到目标时写入 `unlocked_at`；
6. 已经解锁的记录不得因为原始数据被删除而重新锁定；
7. 返回定义和进度的组合结果。

该方案避免首版修改训练主链路。代价是 `unlocked_at` 表示系统首次同步到已达成状态的时间，不保证等于行为发生的精确时间。

概览服务分别取得学习日历和按日保存资产数，再以 `LocalDate` 合并：

- `summary.savedAssetCount` 只来自 `LearningAssetCountPort.countSavedAssets`；
- `calendar.days[].savedAssetCount` 只来自 `LearningAssetCountPort.countSavedAssetsByDate`；
- 某天没有资产记录时填零；
- 学习统计模块不承担学习资产统计，避免数据归属混乱。

当未来需要精确解锁时间时，再由训练、资产和评分模块发布领域事件；当前版本不提前引入消息队列。

## 10. 账户删除流程

```text
用户确认注销
  -> 验证当前密码
  -> user.status = PENDING_DELETION
  -> auth_version + 1
  -> 所有设备退出
  -> 等待 30 天
       |-- 用户撤销 -> ACTIVE + 清空注销时间 + 签发新 Token
       `-- 到期 -> AccountDeletionCoordinator
                    |-- 删除头像对象
                    |-- 删除/匿名化各业务域用户数据
                    `-- 最后删除 "user" 行
```

永久删除必须满足：

- 先删除业务数据，最后删除账号主记录；
- 每个模块提供幂等的用户数据删除端口；
- 任一模块失败时保留账号主记录并记录重试状态；
- 不在日志中记录密码、Token、长期用户资料或完整对象 URL；
- `user_achievement_progress` 通过外键级联删除；
- 永久删除任务的调度周期不超过 24 小时；
- 当前仓库缺少其他业务表完整迁移与删除契约，执行永久删除前必须取得相关模块授权。

## 11. 前端行为

### 11.1 个人概览

- 进入 `/profile` 后请求 `/api/profile/overview`；
- 用真实数据替换 `learningMonths`、`achievements` 和固定统计值；
- 点击“已保存学习资产”跳转 `/assets`；
- 页面保留现有布局；
- 提供加载、空数据、错误和重试状态；
- 切换月份时重新请求对应 `yearMonth`。

### 11.2 账号资料

- AI 老师头像与用户头像完全分离；
- 未设置用户头像时显示昵称首字母或默认头像；
- 昵称保存成功后同步更新侧栏和个人中心；
- 上传头像时显示上传中和失败状态；
- 不允许前端自行拼接对象存储密钥或对象键。

### 11.3 助手设置

- 继续复用现有 `SpeedSelector`、`LevelSelect` 和 `TeacherSelector`；
- 继续使用 `GET/PUT /api/user-preferences`；
- 自由对话和个人中心共用同一份顶层状态；
- 不复制组件、不增加第二套设置接口。

### 11.4 安全与隐私

- 修改密码成功后清除 Token；
- 注销账户必须输入当前密码并二次确认；
- 长期用户资料可查看、编辑和清空；
- 危险操作不能只依赖浏览器确认框；
- 所有提交按钮都需要防止重复提交。

## 12. 错误码

新增并保持稳定：

| 错误码 | HTTP 状态 | 含义 |
| --- | ---: | --- |
| `CURRENT_PASSWORD_INVALID` | 400 | 当前密码不匹配 |
| `NEW_PASSWORD_SAME_AS_CURRENT` | 400 | 新旧密码相同 |
| `AVATAR_FILE_TOO_LARGE` | 400 | 头像超过 2 MiB |
| `AVATAR_FILE_TYPE_UNSUPPORTED` | 400 | 头像类型不支持 |
| `AVATAR_STORAGE_FAILED` | 503 | 对象存储不可用 |
| `ACCOUNT_PENDING_DELETION` | 403 | 账户正在等待删除 |
| `ACCOUNT_REACTIVATION_NOT_ALLOWED` | 400 | 不满足恢复条件 |
| `PROFILE_OVERVIEW_UNAVAILABLE` | 503 | 个人概览依赖查询失败 |
| `ACHIEVEMENT_METRIC_UNSUPPORTED` | 500 | 启用的指标没有实现 |

认证失败相关接口不得通过错误信息区分“用户不存在”和“密码错误”。

## 13. 安全要求

- 所有账户修改接口从 Spring Security 上下文获取当前用户；
- 所有按用户查询的 SQL 必须包含 `user_id = #{userId}`；
- 头像校验不得只信任文件扩展名或 `Content-Type`；
- 对象存储访问密钥只从环境变量或部署密钥读取；
- 密码永不写入日志；
- 修改密码和申请注销使用事务；
- 修改密码、申请注销、撤销注销需要限流能力；首版至少保留稳定错误码和审计日志接口边界；
- 头像对象键由服务端生成，不能接受前端指定；
- 永久删除任务必须幂等。

## 15. ADR 摘要

### ADR-001：采用窄范围聚合接口

- 决定：使用 `/api/profile/overview` 聚合统计、日历、资产数和成就。
- 放弃：前端分别编排多个个人概览接口。
- 原因：页面固定同时需要这些数据，单接口可以统一加载与错误处理。
- 代价：聚合服务依赖多个公开查询端口。

### ADR-002：头像保存对象键

- 决定：数据库保存 `avatar_object_key`，运行时生成 URL。
- 放弃：数据库保存图片二进制或固定 CDN URL。
- 原因：避免数据库膨胀，并允许更换访问域名。
- 代价：返回账号资料时需要调用 URL 解析器。

### ADR-003：密码修改使所有设备退出

- 决定：密码更新与 `auth_version + 1` 同事务。
- 放弃：只退出当前设备。
- 原因：密码变更通常意味着凭证可能泄露。
- 代价：用户必须在所有设备重新登录。

### ADR-004：账户延迟 30 天删除

- 决定：先进入 `PENDING_DELETION`，30 天后永久删除，期间允许恢复。
- 放弃：立即硬删除。
- 原因：降低误操作造成的不可恢复损失。
- 代价：需要恢复接口、调度任务和跨模块删除协调。

### ADR-005：成就定义与进度独立持久化

- 决定：使用 `achievement_definitions` 和 `user_achievement_progress`。
- 放弃：把成就 JSON 塞入 `"user"` 表。
- 原因：支持规则启停、排序、进度和解锁时间的规范查询。
- 代价：增加两张表及指标同步逻辑。
