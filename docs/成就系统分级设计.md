# 成就系统分级设计

## 1. 文档目标

本文档定义 UniSpeaking 第一版动态成就系统。设计只使用当前数据库已经持久化、能够按用户可靠归属的数据，不把前端静态进度视为真实业务数据。为了支持首次达成弹窗、跨设备去重和失败重试，第一版同时持久化用户成就解锁与展示确认状态。

第一版保留当前可实现的 8 个成就，并将相同指标组织为可持续晋升的成就系列；当前缺少数据依据的成就和依赖其他成就的派生成就从范围中移除。

## 2. 统一计算口径

- 业务时区统一使用 `Asia/Shanghai`。
- 有效对话必须来自 `practice_session`，状态为 `COMPLETED`，且单次持续时间不少于 30 秒。
- 打卡日期由已经持久化的 `session_evaluation.created_at` 转换为业务日期，同一天存在多份报告时只计算一次。
- 连续学习使用“历史最长连续打卡天数”，不能因为当前连续记录中断而撤销已经获得的成就。
- 月度打卡使用“历史任意自然月的最高打卡天数”，已经完成的月度成就不得因月份切换而失效。
- 分数类成就使用历史最佳值或历史达标次数，不使用最近一次成绩覆盖历史最好成绩。
- 资产类成就统计用户历史上曾经拥有的学习资产。场景软删除后不撤销已经获得的成就。
- 所有成就进度只能保持或增长，不能因为删除资产、连续记录中断或进入新月份而倒退。
- 成就进度由业务事实动态计算，首次解锁时间和弹窗展示状态由服务端独立持久化。
- 客户端只能请求服务端重新计算成就，不能上传进度、修改阈值或声明成就已经达成。
- 同一成就只在首次达成后进入待展示队列；展示确认必须跨刷新和跨设备生效。

## 6. 数据归属与历史边界

### 6.1 用户归属

- `practice_session` 可以直接使用 `user_id` 归属用户。
- `scene` 可以直接使用 `user_id` 归属用户。
- `turn_evaluation`、`session_evaluation` 优先通过 `session_id` 关联 `practice_session` 确认用户归属。
- `sentence_evaluation` 通过 `scene_id` 关联 `scene.user_id` 确认用户归属。
- 不信任客户端传入的 `userId`，成就查询必须使用 JWT 对应的当前用户。

### 6.2 历史数据限制

`practice_session` 是后续增加的全场景会话事实表。若上线迁移时没有对旧会话进行回填，则以下指标只能覆盖该表启用后的行为：

- 有效对话次数。
- 累计学习时长。
- 已完成的不同场景数量。
- 练习类型覆盖数量。

评分、打卡和跟读类成就可以继续利用已经存在的历史评分记录，但必须确保能够可靠关联到所属用户。

## 7. 进度与解锁规则

每个成就系列至少需要输出以下信息：

- 稳定的系列 ID。
- 系列名称和分类。
- 当前统计值与展示单位。
- 当前已经达到的最高等级。
- 下一等级的阈值、称号和剩余进度。
- 全部晋升节点及各节点是否已经解锁。

建议的进度规则如下：

1. 未达到第 1 级时，进度条目标为第 1 级阈值。
2. 达到某一级后，进度条自动切换到下一等级阈值。
3. 达到最高等级后显示“已完成”，不再显示下一等级。
4. 系列进度百分比按“当前值 / 下一等级阈值”计算，最大为 100%。
5. 分数类指标最高值限制为 100，次数、天数和时长类指标不设置展示上限。
6. 某一节点一旦满足，必须通过历史最大值、历史累计值和解锁记录共同保证其不会重新锁定。
7. 服务端同步时计算全部 48 个节点，只为已经满足且尚无记录的节点创建解锁记录。
8. 重复同步和并发同步不能产生重复记录，数据库复合主键是最终幂等保障。
9. 未完成展示确认的成就在后续同步时继续返回，确认后的成就不再进入待展示队列。
10. 解锁同步失败不能回滚或阻塞练习、评分、学习资产等核心业务结果。

## 8. 解锁状态持久化

### 8.1 `user_achievement_unlock`

保存用户已经达成的具体成就节点及弹窗状态。

| 字段 | 类型 | 约束与用途 |
|---|---|---|
| `user_id` | `UUID` | 当前用户 ID，与 `achievement_id` 组成复合主键 |
| `achievement_id` | `VARCHAR(64)` | 稳定节点 ID，例如 `conversation-1`，不能为空 |
| `unlocked_at` | `TIMESTAMPTZ` | 服务端首次确认达成的时间 |
| `acknowledged_at` | `TIMESTAMPTZ` | 弹窗已经展示并关闭的时间；为空表示等待展示 |
| `created_at` | `TIMESTAMPTZ` | 记录创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 记录最后更新时间 |

规则：

- 复合主键固定为 `user_id + achievement_id`。
- 不设置数据库外键，由 Repository 和 Service 校验用户归属。
- `acknowledged_at IS NULL` 的记录按 `unlocked_at` 和成就目录顺序进入待展示队列。
- 并发插入相同复合主键时，将重复键视为已经解锁，不能转化为接口失败。
- 展示确认只允许从空值更新为服务器当前时间，已经确认的记录保持幂等。

### 8.2 `user_achievement_state`

区分用户首次历史初始化与后续正常增量解锁。

| 字段 | 类型 | 约束与用途 |
|---|---|---|
| `user_id` | `UUID` | 主键，用户 ID |
| `initialized_at` | `TIMESTAMPTZ` | 首次完成历史成就初始化的时间 |
| `created_at` | `TIMESTAMPTZ` | 记录创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 记录最后更新时间 |

不存在状态记录时表示用户尚未完成成就系统初始化。初始化完成后，无论用户当时是否已满足成就，都必须保存状态记录，避免下一次同步重复进入初始化流程。

## 9. HTTP 接口

所有接口从 JWT 获取当前用户，使用统一 `ApiResponse`，不接受客户端传入的 `userId`。

### 9.1 查询成就进度

```http
GET /api/achievements
```

只读取当前用户的实时进度和已解锁状态，不创建解锁记录。响应包含：

- 10 个成就系列及分类。
- 每个系列的当前统计值、当前最高等级和下一等级。
- 48 个节点的阈值、称号、说明和解锁状态。

### 9.2 同步成就解锁

```http
POST /api/achievement-unlocks
```

服务端重新计算全部指标，创建本次新满足的解锁记录，并返回：

- 最新成就系列进度。
- 本次新解锁节点。
- 之前尚未确认展示的待展示节点。

接口必须幂等。客户端请求同步不是进度事实，只是触发服务端根据数据库事实重新计算。

### 9.3 确认弹窗已经展示

```http
PATCH /api/achievement-unlocks/{achievementId}
```

请求体：

```json
{
  "acknowledged": true
}
```

服务端只允许确认当前用户已经解锁的节点。不存在、尚未解锁或属于其他用户的记录不能被确认。

## 10. 中央达成弹窗

成就达成弹窗是应用级组件，挂载在全局应用壳层中，不依赖用户是否正在个人主页。

交互规则：

1. 弹窗位于页面中心，展示成就系列、等级、称号、达成条件和对应图标。
2. 同时存在多个待展示节点时逐个展示，不叠加多个弹窗。
3. 队列按解锁时间排序；同一批次时间相同时按成就目录和等级排序。
4. 用户可以手动关闭，默认 5 秒后自动关闭；关闭当前节点后再展示下一个节点。
5. 每次关闭后调用展示确认接口；确认失败时不阻塞下一节点，但该节点保留为待重试状态。
6. 成就弹窗可以覆盖在评分结果弹窗上方，关闭后原评分结果必须保持不变。
7. 弹窗队列在页面导航过程中保持，退出登录时必须清空。
8. 前端只根据服务端返回的 `seriesId` 选择图标，不复制阈值和解锁判断。

成就同步时机：

- 登录、注册完成或已有登录态恢复时。
- 有效自由对话结束后。
- 自定义场景对话和五维评分持久化后。
- 单轮表达评分持久化后。
- 句子跟读评分持久化后。
- 场景生成并保存为学习资产后。
- 后续 IELTS、面试等场景完成并写入统一业务事实后。

某次同步失败时不立即打断用户，下一次业务完成或登录恢复时再次同步。

## 11. 历史用户初始化

第一版上线时，历史用户可能已经满足多个成就。为避免首次登录连续弹出大量旧成就，采用静默初始化：

1. 用户首次调用同步接口且不存在 `user_achievement_state` 时，服务端计算全部历史成就。
2. 为已经满足的节点创建 `user_achievement_unlock`，并同时填写 `unlocked_at` 和 `acknowledged_at`。
3. 创建 `user_achievement_state`，标记初始化完成。
4. 本次响应不把这些历史节点放入待展示队列。
5. 初始化完成后新满足的节点正常以 `acknowledged_at = NULL` 写入并触发弹窗。

新注册用户需要在进入练习前完成一次同步。即使当时没有满足任何节点，也要创建初始化状态，使其随后达成的首个成就可以正常弹出。

## 12. 第一版实施边界

第一版实现范围：

- 返回 10 个成就系列及其 48 个晋升节点。
- 使用真实数据库数据计算当前用户进度。
- 保存首次解锁时间、历史初始化状态和弹窗展示确认状态。
- 在应用中心逐个展示新达成成就，并支持失败重试。
- 保留“开口、连续、场景、成长”四个现有分类。
- 前端展示系列当前等级、下一等级和完整里程碑。
- 不新增手动领奖、奖励发放、经验值、积分或排行榜。
- 不新增补签、管理员修改进度或客户端上报成就进度接口。
- 不新增用户自定义周目标。
- 不引入 Redis、消息队列或客户端本地存储作为成就真相来源。

成就定义和阈值第一版保存在服务端稳定目录中，不增加运营配置表。后续只有在需要后台动态配置、奖励发放或版本化运营活动时，才评估增加成就定义表和奖励流水表。
